# WIE 网页版本地适配说明

本轮只改 `wie-web` 网页层，不修改 Rust 模拟器核心，便于后续合并上游兼容性更新。

## 改动

- 默认语言改为简体中文；新增 `zh-CN` 词条，设置里保留韩语、英语及跟随系统。
- 页面标题、菜单、提示、按键说明、错误提示已中文化；游戏画面内文字不由网页语言设置控制。
- 新增 URL 参数自动载入：`f=<游戏 ZIP/JAR 地址>` 或 `res=<游戏 ZIP/JAR 地址>`；兼容 `app_url=`、`game_url=`。可选 `title=<游戏名>` 用于下载链接没有正确扩展名时命名。
- 自动载入复用现有 `backend.importApp()` 与资料库启动流程；首次下载后导入，重复打开同文件会替换资料库中同名记录，避免弹出“已添加”错误。
- 加载期间显示中文状态；失败时保留可关闭的错误提示，不再自动抛给全局 Sentry 弹窗。

## 对接方式

与 `_emu_push/mrp` 现成运行器一致，把游戏包的直链放在 `f=` 参数里，例如：

```text
https://<你的 WIE 静态站>/?f=https%3A%2F%2F<资源站>%2Fgame.zip
```

实际部署时资源站与 WIE 静态站需允许跨域读取，或使用同源资源代理；ZIP 要原样传入，不要先解压。App 端仍可通过后台运行器配置指向这个地址，常规接入不需要重新打包 App。

上游已有 `.github/workflows/web.yaml`：GitHub Actions 会在其运行器里安装 `wasm-pack`、执行 `npm run build`，并上传 `wie-web/dist` 静态产物；本机无需安装 Rust/WASM 工具链。把本目录改动提交到自己的分支后，用该流程生成的 `dist` 部署即可；后续合并上游更新时保留这几个网页层文件。

## 本轮验证与边界

- 已用项目内 TypeScript 编译器对改动涉及的网页 TS 文件做 `--noEmit` 类型检查：通过（`@pkg` 为构建时生成的 WASM 包，检查时只用了临时类型桩，已删除）。
- 已检查 `[LGT]체스마스터-国际象棋.zip`：包含 WIE LGT 识别所需的 `app_info`、`000186FF.jar`（ZIP/JAR 格式）与图标文件。
- 按用户要求，未执行 WASM 打包、未做本地浏览器实跑或 App WebView 实跑；上游网页运行能力以用户已实测为准。上线部署前仍需在目标静态站实际打开一次带 `f=` 的链接，确认跨域、资源下载和 WebView 表现。
- 上游自动构建配置已存在，本轮未改；站点运行器条目和静态站部署目标尚未配置，后续按实际域名补齐。
- URL 参数的一键启动流程未在浏览器实跑，属于部署前必须做的一次验收。
